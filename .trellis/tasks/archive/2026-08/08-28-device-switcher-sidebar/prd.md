# 重构侧边栏设备切换器

## Goal

将多设备切换器从侧边栏底部迁移到 Logo 下方，形成常驻、可识别当前设备且支持键盘操作的顶部设备选择卡片。

## Requirements

- 删除正常面板和无设备面板中侧边栏底部的旧设备容器，以及旧容器展示的连接状态、ROS 版本和运行时间信息。
- 在 Logo/版本信息下方、导航菜单上方渲染紧凑的设备切换卡片：展示状态圆点、当前设备名、辅助信息和展开箭头。
- 展开后列出所有启用且未归档的设备；每项展示状态、名称、可用的 RouterOS 地址/名称，并高亮当前设备和显示选中标识。
- 设备切换继续写入现有的 `selectedDeviceID` 全局状态，复用既有刷新 effect，使单设备页面重新读取对应设备数据；不新增后端接口或第二套设备状态。
- 保持侧边栏现有浅色/深色主题、导航状态和移动端抽屉行为；卡片及选项提供可见焦点、悬停/展开反馈和可读的 ARIA 状态。
- 设备地址优先从已加载的 `/api/settings` 设备配置读取；配置尚未到达时使用 RouterOS 名称或明确的等待/异常状态作为降级信息。
- 设备切换器视觉信息保持两行：第一行状态圆点与设备名，第二行仅显示 IP/地址；触发器固定为 48px，选项固定为 44px，勾选和箭头保持右侧垂直居中。
- 在本地检查通过后，将嵌入前端资源和 Linux amd64 二进制部署到 `10.0.0.6` 的现有 systemd 服务；部署前在本机 NAS 创建包含旧二进制、配置、SQLite 主库及 sidecar、服务单元的时间戳回滚备份。
- 部署后验证 systemd 服务、`/api/health`、设备 API 和嵌入前端资源，停在用户手工打开 `10.0.0.6:8080` 检查并明确批准之后再提交代码。

## Acceptance Criteria

- [x] `.sidebar-device-card` 旧底部组件及其专用选择框/状态详情不再由两种侧边栏布局渲染，也不再保留无效专用 CSS。
- [x] 正常面板的设备卡片位于 Logo 后、导航前；触发器和选项已紧凑化，点击/键盘操作可展开、关闭并切换设备，当前项有状态高亮和 checkmark。
- [x] 切换设备后 `selectedDeviceID` 改变，现有单设备请求以新设备 ID 重新触发，仪表台列表进入详情的联动仍然有效。
- [x] 无设备面板没有左下角冗余设备容器，侧边栏仍能正常显示导航和空状态。
- [x] `npm --prefix web run lint`、`npm --prefix web run build` 与 `go vet ./...` 通过。
- [ ] 手工检查桌面宽度和移动端抽屉：卡片不被侧边栏裁切，菜单不造成页面横向溢出，键盘焦点可见。
- [x] `10.0.0.6` 部署前已在本机 NAS 留存可回滚的二进制、配置、SQLite 数据（含 sidecar）和 systemd 单元备份：`backups/20260828T012352Z-net-device-switcher-current/`。
- [x] `10.0.0.6` 上 systemd、健康接口、设备 API 和嵌入前端资源验证通过，并等待用户手工验收。
- [ ] 用户明确批准部署结果后，才提交实现并归档任务。
