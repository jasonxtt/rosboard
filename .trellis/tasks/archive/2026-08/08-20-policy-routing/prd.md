# RouterOS 域名策略路由管理 PRD

## 1. 文档状态

- 状态：需求已冻结，等待用户审阅规划文档。
- 产品：rosboard。
- 首版 RouterOS 基线：7.17；具体功能按运行时能力继续细分。
- 实验设备：`10.0.0.99`。会话中提供的凭据是临时运行时秘密，不得进入文档、代码、配置、数据库、日志、截图或版本库。
- 本文档只定义需求、约束和验收标准，不授权启动实现或写入实验设备。

## 2. 背景与目标

rosboard 当前以 RouterOS 只读状态监控为主。用户需要在 rosboard 中集中管理基于域名的策略路由：从远程或本地 Clash YAML 提取域名，转换为 RouterOS DNS Static FWD 并关联 address-list，再补齐指定 WAN 所需的路由表、默认路由、mangle、NAT、DNS 和防火墙配套设置。

首版目标是在不创建或重构 WAN 接入线路的前提下，让用户安全、可预览、可回滚地将一组或多组域名绑定到明确的 IPv4/IPv6 WAN 出口，并持续同步域名来源。

成功结果必须满足：

1. 只有 rosboard 明确拥有的 RouterOS 对象才会被修改或删除。
2. 已工作的 WAN 是前置条件，但策略路由缺少的安全且明确的配套对象由 rosboard 自动补齐。
3. 两 WAN 等简单环境默认只需一个共享 address-list 和一组业务 mangle；需要不同来源独立控制时可使用多个出口或高级专用列表。
4. IPv4 与 IPv6 可独立启用，并共用不带 `_v4`、`_v6` 后缀的逻辑名称。
5. 首次启用、结构变更和删除均经过检查、差异预览、备份、确认、应用、验证及必要的定向回滚。

## 3. 用户与核心对象

- **目标用户**：已配置多 WAN、希望按域名指定出口的 RouterOS 管理员；管理多台 RouterOS 的 rosboard 管理员；希望接管现有手工方案的管理员。
- **受管设备**：全局设备选择器当前选中的 RouterOS。
- **出口策略**：目标 WAN、IPv4/IPv6 映射、路由行为、DNS 上游、address-list 模式、优先级和失败策略的集合。
- **域名来源**：隶属于出口策略的远程 URL 或上传 YAML，可独立启停、更新、改名、迁移和删除。
- **受管对象**：带稳定 rosboard 所有权标识，并在 SQLite 中记录 RouterOS `.id` 与前置状态的对象。
- **复用对象**：兼容但仍归用户所有的 RouterOS 对象；rosboard 只引用，不改写或删除。

## 4. 首版范围

### 4.1 包含

- 一级菜单“主机设置”及其首个二级菜单“策略路由”。
- 每设备独立启用写管理与最小权限策略账号。
- 公共 HTTPS Clash YAML、浏览器本地 Clash YAML 上传。
- `DOMAIN`、`DOMAIN-SUFFIX` 解析、规范化、预览、搜索、导出和同步。
- 每出口共享 address-list，以及高级每来源专用 address-list。
- IPv4、IPv6 或双栈策略；双栈共用逻辑名称。
- 发现、复用或补建明确安全的策略路由表、默认路由、DNS forwarder、DNS Static、mangle、NAT、DNS 访问和 FastTrack 配套对象。
- 默认 WAN 与非默认 WAN 作为显式策略出口。
- 严格模式、显式回落 `main` 模式、现有表故障切换复用模式。
- 定时同步、手动刷新、漂移检测、审计、历史版本、持久化任务、取消和定向回滚。
- 严格匹配后接管手工配置，以及旧 rosboard 实例不可用时的高风险强制接管。
- 在 `10.0.0.99` 分阶段实机验收；rosboard 构建部署仍遵循 `10.0.0.6` 人工验收门禁。

### 4.2 不包含

- 创建或修改 PPPoE、DHCP Client、WireGuard、WAN 地址或运营商接入。
- 自动配置非 `main` VRF、BGP、OSPF、MPLS、路由过滤器或动态协议策略默认路由。
- 多个 rosboard 实例同时或拆分管理同一台 RouterOS。
- 按客户端、用户、来源子网或不同 VLAN 使用不同域名策略。
- 在线逐条编辑域名、手工例外规则或本地覆盖层。
- Clash `payload` 以外的 hosts、Surge、纯文本、GEOSITE、正则或 IP-CIDR 来源。
- DoH、DoT、DNSCrypt、代理辅助 DNS、多个策略 DNS 上游及其负载均衡或故障切换。
- 阻断客户端 DoH、DoT、QUIC 或浏览器私有 DNS。
- WAN 故障后自动切到另一个非默认 WAN；内置公网 IP 回显服务。
- RouterOS 手工改动反向同步进 SQLite。
- 无预览的一键历史回滚、自动导入完整 RouterOS 配置或自动清除 conntrack。
- 自动接管无法严格识别所有权和完整关系的对象。

## 5. 功能需求

### FR-1 导航与设备作用域

1. 新增一级菜单“主机设置”；现有“状态监控”保持只读语义。
2. “策略路由”是首版“主机设置”下唯一二级菜单。
3. 页面作用于全局当前设备，切换设备后不得混用策略、任务、凭据、历史或告警。
4. 首页展示能力与权限、版本、LAN 范围、漂移、健康、同步、待审阅任务、出口策略和域名来源。

### FR-2 权限、凭据与操作确认

1. 现有只读监控账号继续使用；策略管理使用每设备独立账号。
2. 默认生成随机账号、专用 group 和幂等初始化脚本；权限仅 `read,write,test,api,rest-api`，不得含 `policy`。
3. 高级流程可使用用户现有写账号，但必须验证能力。
4. 策略账号凭据只保存在权限 `0600` 的私有 YAML，不通过 API 返回，也不写入日志、导出和 SQLite。
5. 初次启用、结构变更、优先级调整、破坏性操作、漂移处理和接管，最终确认时必须验证当前 rosboard 管理员密码。
6. 二次验证只授权当前一次已预览操作；失败不得发生 RouterOS 写入。定时同步和非结构性域名增量不要求交互验证。
7. 无受管写功能时可生成自建策略账号清理脚本；用户提供的 RouterOS 账号不得由 rosboard 删除。

### FR-3 RouterOS 版本与能力

1. named DNS forwarder 方案基线为 RouterOS 7.17，并运行时探测 API、字段和对象能力，不以 7.22.3 为最低版本。
2. DHCP Client 原生 `default-route-tables` 自动补路由要求 RouterOS 7.18。
3. RouterOS 7.17 DHCP WAN 不生成或合并 lease script；仅阻止该出口自动补路由并提示升级，其他出口仍可用。
4. IPv4/IPv6 能力分别判断；缺少 IPv6 前置条件不得影响工作中的 IPv4。

### FR-4 出口策略与命名

1. 出口候选依据实际路由、网关、接口类型和运行状态发现，不依赖接口命名；用户做最终选择。
2. 默认 WAN 可被选择。复用 `main` 时提示继承 ECMP、故障切换和未来变化，且不标记为严格绑定。
3. 严格绑定使用新建或可证明只到达目标 WAN 的专用路由表。
4. 双栈逻辑出口允许 IPv4、IPv6 映射到不同的已验证接口或下一跳。
5. rosboard 新建双栈对象使用一个无地址族后缀的路由表、address-list、connection mark 和 routing mark 命名空间，分别建立 IPv4/IPv6 规则。
6. 已有拓扑若分开使用 IPv4/IPv6 表，可在一个逻辑出口内映射，复用表仍归用户。
7. 共享列表默认名 `manual_proxy_lab`；专用来源默认名 `manual_<source-slug>_lab`。名称可编辑且改名属于结构变更，不加 `_v4`/`_v6`。
8. 已有列表只有在展示全部条目和引用并明确确认后才可复用；其所有现有及未来条目都会受策略影响，rosboard 只删除自己加入的条目。

### FR-5 address-list 模式与归属

1. 默认共享模式为每出口一个 address-list，多来源共用一组业务 mangle。
2. 高级专用模式为每来源建立独立 address-list 和对应策略规则。
3. 来源归属保存在 SQLite；RouterOS `comment` 使用稳定 ID 和可读名称，不含地址族后缀。
4. 共享模式下，相同出口、相同规则类型和相同规范化域名只物化一条 DNS Static；SQLite 保存多来源引用。
5. 最后一个来源引用消失后才删除共享条目；注释能容纳时列出来源名，否则显示来源数量和稳定 ID。
6. 专用模式不跨来源合并。`DOMAIN` 与 `DOMAIN-SUFFIX` 即使文本相同也不得合并。

### FR-6 域名来源与解析

1. 远程来源只接受公共 HTTPS；已知 GitHub `blob` URL 自动转 raw。
2. URL 不得含凭据或 fragment。初始地址和每次重定向都重新解析，拒绝回环、私网、链路本地、多播、保留及其他非公网地址。
3. 下载限制 5 MiB、15 秒、最多 5 次重定向，最终响应必须为文本/YAML。
4. 来源由 rosboard 后端通过 rosboard 主机网络下载；RouterOS 不保存 URL，不创建 fetch、Scheduler 或来源文件。
5. 上传来源接受浏览器本地 `.yaml`/`.yml`，同样限制 5 MiB；不读取或监视服务器任意路径。
6. 两种来源只解析顶层 `payload` 中的 Clash `DOMAIN` 与 `DOMAIN-SUFFIX`。
7. `DOMAIN` 为精确匹配且 `match-subdomain=no`；`DOMAIN-SUFFIX` 为后缀匹配且 `match-subdomain=yes`。
8. 域名转小写、去末尾点、校验并按语义去重，不能扩大精确匹配范围。
9. 不支持类型按类型显示数量和原因；YAML 无效或有效域名为零时失败并保留 last-good。
10. 首次创建或替换 URL/文件，先显示解析及新增、删除、忽略、重复、冲突统计，再允许应用。
11. URL 默认每 24 小时更新，可改手动或其他间隔；支持手动刷新、ETag/Last-Modified，无变化时不写 RouterOS。
12. 上传来源仅在重新上传后更新，无定时计划。
13. 来源可编辑名称、URL或上传版本、计划、出口、启用状态和列表模式；单条域名只读、可搜索、分页和导出。

### FR-7 冲突与优先级

1. 同一出口内重复来源规则允许存在并报告冗余。
2. 不同出口间相同精确域名或精确/后缀包含冲突时阻止应用。
3. CDN 等导致的运行时 IP 重叠只告警；出口具有共享 IPv4/IPv6 优先级，高优先级先匹配。
4. 调整优先级属于结构变更，必须预览 mangle 顺序。
5. 预检比较启用中的用户 DNS Static，包括 FWD、A/AAAA、CNAME、NXDOMAIN 和正则；检测到覆盖冲突默认阻止。
6. 只有行为、forwarder、address-list 和出口完全兼容时才可显式复用 DNS 对象，且对象仍归用户。

### FR-8 路由表与默认路由补全

1. WAN 已存在并可联网是前置条件；rosboard 不创建或重构 WAN。
2. 检查策略所需 routing table 和 marked default route：兼容则复用，缺少则在路径可唯一推导时补建，否则要求用户选择。
3. 新建 routing table 必须为 `fib`。
4. 静态网关通过可验证 next-hop 与 `main` 解析；PPPoE、WireGuard 等点到点出口可使用接口路由。
5. RouterOS 7.18+ DHCP WAN 通过 `default-route-tables` 追加策略表并保留已有值；删除时仅撤回 rosboard 增量。
6. 复用表前检查每个地址族全部默认路由、distance、ECMP、黑洞和最终出口。
7. 严格模式只能复用所有转发默认路由都到达目标 WAN 的表；不兼容时建议专用表，不能禁用或删除用户路由。
8. 用户可在看见全部可能出口后选择沿用现有表故障切换，但不得标记为严格。
9. 默认严格模式为每个启用地址族添加高 distance 的自有 blackhole default，WAN 故障时不得泄漏至 `main`。
10. 显式 fallback 模式允许回到 `main`，必须提示流量可能走非预期出口；IPv4/IPv6 健康分别评估，不自动切到另一非默认 WAN。
11. 普通 `main` 路由域中的静态、DHCP、PPPoE、WireGuard WAN 属于自动化范围。
12. 递归、ECMP、BGP、OSPF、非 `main` VRF、MPLS 和路由过滤器只检测展示。只有能证明完整默认路由最终出口的复杂表才可复用。
13. 需要修改 VRF、动态协议或过滤器的场景阻止且没有强制忽略开关。

### FR-9 DNS、Fake DNS 与客户端范围

1. 每出口自动分配一个经冲突检查的 Fake DNS 别名和一个可编辑真实上游，默认 `1.1.1.1`。
2. 双栈通常通过同一 IPv4 DNS 传输获取 A/AAAA，分别进入同名 IPv4/IPv6 firewall address-list；仅 IPv6 策略使用 IPv6 Fake DNS 和 IPv6 上游。
3. 首版上游只支持一个 IPv4 或 IPv6 地址的 UDP/TCP 53，不支持加密 DNS、负载均衡和上游故障切换；UI 说明查询未加密。
4. 已有全局 DoH 必须展示；无法证明 named forwarder 仍使用指定上游和出口时阻止启用。
5. RouterOS 生成的策略 DNS 转发流量必须通过 output mangle/DNAT 和目标策略表经所选 WAN 发出。
6. 每设备使用一个经确认、由全部出口和来源共享的受管 LAN 范围。
7. 优先复用兼容 `LAN` interface list，否则可从用户选择的 LAN/VLAN/WireGuard 接口创建自有列表；终端范围推断只提供候选。
8. DNS 访问、可选 53 重定向和 IPv4/IPv6 策略 mangle 使用同一范围。
9. 基础 DNS 集成默认开启：需要时启用 `allow-remote-requests`，补齐仅可信 LAN 的 TCP/UDP 53 input，并在展示前后值后允许更新兼容 DHCP network 的 DNS 广播。
10. 静态客户端提示手动使用 RouterOS DNS；外部 TCP/UDP 53 重定向是高级选项，具有独立所有权和回滚状态。
11. 不阻断 DoH、DoT、QUIC 或浏览器私有 DNS，持续提示可绕过域名发现。

### FR-10 防火墙、FastTrack 与 NAT

1. 受管策略和 DNS 规则插入通用 PCC/PBR 之前，且不改变用户规则之间相对顺序。
2. FastTrack 会包含策略连接时，新增自有 pre-FastTrack bypass/accept，不编辑用户 FastTrack。
3. 无法确定安全插入位置时阻止并指出冲突对象及所需位置。
4. 开启远程 DNS 前检查 TCP/UDP 53 是否仅限可信范围；安全规则复用，覆盖不足时可预览自有可信 allow 与非可信 DNS drop。
5. 复杂防火墙无法判断时默认阻止，但允许显式高风险例外；必须突出开放解析器风险、要求风险确认和管理员二次验证，且不得宣称安全。
6. NAT 优先复用可证明覆盖策略路径的现有规则。
7. 覆盖缺失时只建立窄范围自有 NAT：动态 IPv4 masquerade；下一跳与地址明确的静态 IPv4 src-nat；路由器策略 DNS 仅覆盖所需流量。
8. 原生 GUA IPv6 默认无 NAT；WireGuard/ULA 等可显式启用同时受目标 address-list 与出口接口约束的策略 IPv6 masquerade。
9. 每个 NAT、防火墙、FastTrack 对象进入差异、验证和所有权感知删除。移除最后 DNS 依赖时只恢复记录的字段增量并删除自有保护规则。

### FR-11 流量作用范围

1. 默认只对经确认 LAN 范围转发的业务流量应用域名策略。
2. 除策略 DNS plumbing 外，不默认改道 RouterOS 自身管理、监控、DDNS、更新、容器或控制面流量。
3. 每出口提供高级“包含 RouterOS 本机流量”；启用前展示受影响服务及现有 output mangle，并建立独立、顺序可验证的自有规则。
4. 无法证明 output 安全插入点时阻止。启停不自动清除 conntrack 或已建立管理连接，UI 提示主要对新连接生效。

### FR-12 同步、状态与生命周期

1. SQLite 是出口、来源、计划、last-good、对象映射、任务和审计的期望状态权威；RouterOS 是同步前必须读取的实际状态。
2. 普通差异增量应用。定时更新使有效域名减少超过 50% 时暂停审阅，旧版本继续生效。
3. 下载、解析或应用失败保留旧版本并显示最后成功时间、错误及新增、删除、忽略、不变、失败数量。
4. 手工修改自有对象形成 drift 并暂停同步，不能静默覆盖。
5. 用户可恢复 rosboard 期望状态，或停止管理并保留 RouterOS 现状；不反向导入手工变化。
6. 停用来源移除有效贡献但保留定义和 last-good；删除先清理验证 RouterOS，成功后再删活动元数据，审计保留。
7. 更新、停用和删除时刷新 DNS cache；共享动态列表可能短暂清空并在查询后重建，必须提示。
8. 删除最后来源不自动删除出口；有关联来源时不得删除出口，必须先迁移或删除来源。
9. 删除出口只删除自有对象和已记录字段增量；复用的用户路由表、路由、NAT 和列表保留。

### FR-13 历史、容量与保留

1. 单来源最多 20,000 条有效规则；单设备最多 50,000 条活动 rosboard DNS Static。
2. 影响超过 10,000 条的操作显示增强资源、内存和耗时警告；预检显示设备 DNS Static 总数、受管数和 free-memory。
3. 定时更新超限时暂停并保留旧版本。
4. 每来源保留最近 10 个成功完整版本：压缩原始 YAML、哈希、解析快照和差异；活动与 last-good 不因轮换丢失。
5. 失败版本只保留时间、错误、HTTP 状态和统计，不保存完整不可信内容。
6. 只轮换该来源最旧非活动版本；操作人、来源版本、RouterOS 与回滚结果等审计元数据长期保留。
7. 历史 YAML 可下载；恢复时作为替换文件重新走预览，不提供一键历史回滚。
8. 删除来源且 RouterOS 清理成功后，删除原始 YAML 和完整域名正文，保留无域名正文的审计。

### FR-14 备份、任务与回滚

1. 初次应用、结构变更和删除前保存不含敏感信息的 RouterOS export，以及受影响对象精确前置快照。
2. 每设备保留最近 10 个策略变更备份。
3. 多对象 REST 写入逐步记录操作、前值、`.id` 和顺序；失败时逆序回滚本次完成步骤。
4. 完整 export 仅用于人工灾难恢复，绝不自动导入。
5. 回滚后重新读取验证；失败时暂停策略和同步，展示已恢复、待恢复、未恢复对象并提供备份下载。
6. 初次应用、大批量同步、删除和回滚使用持久化后台任务，浏览器关闭不影响。
7. 同设备一次仅一个变更任务；手工与定时串行，其他设备和只读监控不受影响。
8. 任务展示下载、解析、备份、写入、排序、缓存刷新、验证阶段及数量。
9. 取消只在安全 REST 边界生效并触发定向回滚。进程重启后先对账，再要求显式继续或回滚。

### FR-15 所有权、接管与多实例

1. 每个 rosboard 安装有稳定 manager instance ID；RouterOS 注释标明实例、设备策略、逻辑对象和类型。
2. 同设备仅一个策略写入者。其他实例对象只读展示，并阻止当前实例同步、修改和删除。
3. 正常迁移先由旧实例释放管理并保留行为，再由新实例接管；不支持并行或拆分管理。
4. 手工配置发现只读。用户选择候选组、来源、出口和可复用对象后，对比期望与现状并显示匹配、缺少、多余和结构不兼容。
5. 只有结构可理解且规则完全匹配的组才能转移所有权；部分、混合、模糊或启发式接管不允许。
6. 接管需备份、完整差异、所有权确认和管理员验证；接管 DNS Static 获得稳定 ID，`.id` 与前置状态写入 SQLite。
7. 路由表、路由、NAT、mangle、forwarder、address-list 可只复用不接管；转移共享基础对象所有权是独立选择，且完整关系必须可证明。
8. 旧实例不可用时，强制接管需确认旧实例已停止，并完成扫描、备份、影响预览、高风险确认和管理员验证；不自动合并状态。

### FR-16 验证与健康

1. 应用后读回字段、所有权、启用状态和规则顺序；默认路由必须 active 且最终出口正确。
2. DNS 验证刷新缓存、解析代表域名、检查 DNS mark/DNAT 计数，并确认 A/AAAA 进入同名 IPv4/IPv6 列表。
3. 一个样本没有 AAAA 不能单独判定 IPv6 失败，应换样本或报告未覆盖。
4. NAT/FastTrack 在可产生测试流量时做结构和计数验证。
5. 自动检查通过为 `configured`；用户从 LAN 客户端独立确认后可标记 `healthy`。
6. 不调用公网 IP 回显服务，也不保存用户观察的公网 IP。
7. 后台发现路由 inactive、drift 或连续同步失败时标记 degraded/action-required，不自动切换 WAN。

### FR-17 UI 交互

1. 向导顺序：出口与地址族 → 路由/NAT/DNS/LAN → 列表模式 → URL 或上传 YAML → 解析预览 → RouterOS 差异 → 确认。
2. 复用、补建、修改、删除和风险例外按对象显示 before/after、所有权与回滚方式。
3. 域名详情支持搜索、筛选、分页，不一次渲染大列表。
4. 桌面和移动端均可查看、刷新、审批和诊断；大任务使用后台进度页。
5. 明确区分 rosboard 主机的规则下载网络与 RouterOS 的目标业务出口。

## 6. 非功能要求

- **安全**：最小权限、最小范围、显式所有权；写入前完成 SSRF/下载约束；敏感数据不进入可观察输出；路由不确定无强制绕过，只有开放解析器判断允许带强警告例外。
- **可靠性**：跨对象变更可中断、对账、定向回滚；浏览器关闭和进程重启不能扩散半配置；失败不得删除 last-good 或改写用户对象。
- **性能**：50,000 条设备级规则下 UI 不全量渲染；长任务不阻塞其他设备监控；同设备写入串行并展示进度。
- **兼容性**：RouterOS 7.17 起按能力启用；分别测试 IPv4-only、IPv6-only、双栈、静态、DHCP、PPPoE、WireGuard；不得静默重排已有复杂防火墙、PCC/PBR、FastTrack 和 DNS Static。

- [ ] AC-05：本地 YAML 可上传、预览、应用、替换；无自动计划，失败保留旧版，服务器任意路径不可用作来源。
- [ ] AC-06：共享模式每出口只有一组业务 mangle，相同规则只物化一次且按引用删除；专用模式保持独立。
- [ ] AC-07：IPv4、IPv6、双栈可独立创建、验证、停用、删除；同名无地址族后缀，一个地址族失败不破坏另一个。
- [ ] AC-08：静态、DHCP、PPPoE、WireGuard 测试拓扑能安全补齐表和默认路由；兼容对象复用，模糊对象阻止且不修改用户配置。
- [ ] AC-09：默认 WAN 可使用严格专用表或警告后的 `main`；strict、fallback、沿用现有表故障切换语义符合预览和故障测试。
- [ ] AC-10：forwarder、Fake DNS、mangle、NAT、FastTrack 配套对象可完整预览、应用、读回验证和清理。
- [ ] AC-11：安全防火墙规则复用，缺少时仅创建受管范围规则；不确定状态默认阻止，例外需风险确认和二次验证。
- [ ] AC-12：不同出口域名冲突阻止；同出口重复去重；运行时 IP 重叠告警并按策略优先级匹配。
- [ ] AC-13：定时/手工同步支持条件请求、增量和 last-good；缩水超过 50%、超容量或任一步失败均暂停且不破坏现状。
- [ ] AC-14：受管对象 drift 可检测并暂停；恢复期望与停止管理均只作用自有对象。
- [ ] AC-15：初次应用、结构变更和删除失败可按 journal 回滚；回滚失败停止同步并准确展示，完整 export 不自动导入。
- [ ] AC-16：后台任务在浏览器关闭和进程重启后可对账；同设备串行，安全取消并回滚，其他设备监控可用。
- [ ] AC-17：严格匹配手工组可在备份、预览、验证后接管；模糊、部分、其他实例对象只读，强制接管走高风险流程。
- [ ] AC-18：20,000/来源、50,000/设备限制可执行；超过 10,000 显示资源警告，详情分页且前端不全量渲染。
