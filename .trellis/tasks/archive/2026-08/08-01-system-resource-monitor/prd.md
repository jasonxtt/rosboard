# 资源监控子项

## 目标

在现有监控导航的“系统运行”分组下新增“资源监控”子项，完整展示 RouterOS `/system/resource` 实际提供的系统资源信息，并沿用现有设备选择、缓存数据和自动刷新行为。

## 背景

- 当前后端已经采集 `/rest/system/resource`，并将部分 CPU、内存、存储和系统信息用于系统概览及负载历史。
- 本次不新增 RouterOS 轮询，不重复采集同一份数据。
- “资源监控”负责当前资源状态；现有“负载历史”继续负责 CPU、内存、存储的历史趋势，避免两个页面职责重复。

## 需求

- R1：在“系统运行”分组下增加“资源监控”，并支持活动状态、刷新、设备切换和页面偏好恢复。
- R2：资源监控使用 `/system/resource` 提供的全部常规字段，包括架构、主板、CPU 型号、CPU 核心数、CPU 频率、总 CPU 负载、空闲/总内存、空闲/总硬盘空间、平台、运行时间、版本、构建时间、出厂软件版本、坏块比例和两项写入扇区计数。
- R3：资源监控额外读取 `/system/resource/cpu`，多核设备逐核展示 CPU 编号、负载、IRQ 占用和 Disk 占用；该子接口不可用时保留总 CPU 负载并明确显示逐核数据不可用。
- R4：CPU、内存和存储以当前状态模块展示；使用率可以由 RouterOS 的总量与空闲量计算，但不得伪造缺失数据。
- R5：系统信息区域展示平台、架构、主板、版本、构建时间、出厂软件版本和运行时间；硬件/IRQ 详情使用只读字段展示，不提供任何控制操作。
- R6：资源页面采用窄列、多行的响应式网格；CPU 模块和系统信息模块可以同一行，模块宽度可压缩，详细列表允许增加高度。
- R7：资源数据继续通过现有 Monitor 快照和现有 dashboard/realtime API 返回，页面不得直接访问 RouterOS，也不得新增重复资源接口。
- R8：资源监控遵循现有全局自动刷新设置；实时刷新异常时保留最后一次有效数据，并显示现有错误/更新时间语义。
- R9：旧的系统概览、负载历史和其他监控子项行为保持不变；新增字段对现有 API 消费者保持向后兼容。
- R10：空值、设备不支持的字段、总量为零和旧后端缺少新增字段时，页面显示 `-` 或不可用状态，不显示错误的 0% 或 NaN。

## 验收标准

- [ ] 导航中可以进入“系统运行 → 资源监控”，当前项状态和分组展开状态正确。
- [ ] 页面能展示 `/system/resource` 的全部字段，且字段名称和数值含义清晰。
- [ ] CPU、内存、存储的使用率和已用量计算正确；空闲/总量缺失或无效时不会出现错误百分比。
- [ ] 资源数据随现有自动刷新更新，切换设备后不会残留上一台设备的数据。
- [ ] 旧页面、旧接口字段、负载历史数据和其他监控功能无回归。
- [ ] 前端 lint/build、后端测试和竞态检查通过。
- [ ] 按项目部署验收门禁完成远端备份、部署、服务/API/嵌入资源验证，并由用户手动验收后再提交代码。

## 不在范围内

- 不增加进程、温度、风扇或 `/system/resource` 体系之外的其他数据。
- 不改变现有负载历史的存储结构和时间范围。
- 不新增 RouterOS 配置写入或任何非只读操作。
