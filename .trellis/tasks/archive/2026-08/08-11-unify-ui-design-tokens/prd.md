# 统一 UI 设计令牌与控件基类

## Goal

消除 `web/src/index.css` 里"同一个视觉约定被手抄多份"的结构性问题：补齐缺失的尺寸/间距令牌层，把重复定义的药丸控件收敛成单一来源，统一 `select` 外观、焦点环、断点写法与表单选择器边界，并让同一种选择行为在界面上只有一套交互。目标是让后续修改一处即生效，而不是靠人记住 8 个散落的 44px。

## Background

近期两个移动端缺陷（概览被列表遮挡、自动刷新控件与刷新按钮不同规格）成因不同，但暴露的是同一类债：

- 令牌体系覆盖颜色、字号、圆角、阴影、动效，却**没有尺寸与间距令牌**（`--space-*` / `--control-h*` 均为 0 处）。交互控件高度实测有 28/32/34/36/38/40/42/44 共 8 种，`gap` 有 15 种取值，"移动端 44px 触控高度"被手抄在 32 处 `height` 与 20 处 `min-height` 中。抄漏一处就是视觉不齐。
- "hairline 药丸控件"在 `index.css:297/300/306/339/521/586` 被平行定义 6 次，`border: 1px solid var(--hairline)` 全文重复 35 次，`padding` 在 12/14px 间摇摆。同一外观有 6 个定义源。
- 组件规则里使用了 `.topbar-controls select` 这类"类 + 标签"选择器（特异性 0-1-1），会压掉后写的单类工具类（0-1-0）——这正是 44px 高度失效的直接原因。
- 焦点环在全局已定义一次（`index.css:128`），却被 13 条规则重复声明，`outline-offset` 出现 0/2/3/-2 四种值。
- 断点写法不统一：`940/959/980/1164` 带 `max-device-width` 兜底，`1212/1217`（DHCP 卡片）没有，同一个 767 断点两种语义。767 断点自身还散在两个块中。
- `appearance: none` 目前只作用于一个 `select`，其余 `select` 的原生箭头留白各不相同（28px / 12px / 8px / 12px），其中 `.data-toolbar select` 根本没给箭头留位置。
- 10 处 `!important` 全部集中在表单，成因是 `.settings-form select, .settings-form input` 这条过宽的选择器与"可选卡片"（checkbox / `.interface-option` / `.theme-option`）打架。
- 类型比例尺注释声明 `11px floor`，但 `1006/1012/1020` 三处硬编码 `10px`；`18px` 图标尺寸出现 3 次未进令牌。
- 同一种"选一个值"在顶部栏有两套交互：主题是自定义 popup（带预览与描述），自动刷新是原生 `select`；两颗圆钮外观一致但点开完全不同。主题设置更有两套 UI 两套 CSS（`.theme-menu-option` 314–319 与 `.theme-option` 823–826），并在 `App.tsx:639` 与 `1590` 重复写 `documentElement.dataset.theme`。

## Requirements

### 通用约束

- 分四期交付，每期独立验证、独立部署、独立等待人工验收后提交；任何一期未验收不得开始下一期的提交。
- 除第四期明确的交互统一外，**不得产生可见的视觉变化**。视觉不变必须以计算样式对比证明，不能只靠肉眼。
- 不改动数据逻辑、接口契约与业务行为；第四期仅改变选择控件的交互形态，不改变其取值集合与生效方式。
- 桌面端（1440px）、中等宽度（1024px / 768px）与移动端（375px / 390px）四个宽度均需验证。
- 令牌只增不改语义：既有令牌的值不得变动，除非在验收标准中显式列出。

### 第一期：令牌层

- 引入交互控件高度令牌与**按角色命名**的间距令牌，取值由现状归并得出，不得凭空造新尺寸。
- 不建按像素值命名的间距比例尺：现状间距是两套互错 4px 尺加五个奇数游离值，在零可见变化约束下无法收敛，纯数值令牌只会给像素值改名而消不掉任何不一致（理由详见 `design.md` §0）。
- 将落在档位上的字面值替换为令牌引用；不落在档位上的值必须逐一决策：并入邻近档位（需证明视觉不变）或显式保留并在设计文档中记录理由。
- 需要产生可见位移才能收敛的项（奇偶网格合流、游离高度并档、断点整体删除 `max-device-width`）登记为可选第五期，不在本轮范围。
- 焦点环收敛为令牌 + 语义化 offset 档位，每处 offset 差异都注明其盒模型理由。清点后确认"与全局重复即可删"不成立——全局规则只覆盖 `button/input/textarea/select` 的 `:focus-visible`，取值等价的声明各有存在理由（div 视口、`summary`、`:focus` 抑制后的恢复对），仅一条真冗余且其删除无法用 cssdiff 证明惰性，故移入第三期（理由详见 `design.md` §3）。
- 审计断点写法与同断点分散块；只有在计算样式和级联最终赢家均不变时才统一或合并。若 `max-device-width` 语义或规则位置会产生可见变化，则保留现状并登记到需真机验证的第五期。
- 类型比例尺自洽：`10px` 与 `18px` 要么进令牌要么改回既有档位，注释与实际一致。

### 第二期：药丸基类与 select

- 药丸控件收敛为单一基类加修饰类，6 处平行定义不再各自重抄外观属性。
- 组件规则中的标签选择器（`select` / `button` / `input`）替换为显式类，消除"类 + 标签"压过单类工具类的特异性陷阱。
- 全部 `select` 统一 `appearance: none` 与自绘指示箭头，箭头留白使用同一令牌，不再出现无留白的 `select`。

### 第三期：表单选择器边界

- 收窄 `.settings-form` 对输入控件的选择范围，使其不再命中可选卡片与勾选框。
- 删除因此不再需要的 `!important`；如有无法删除的，需逐条说明原因。

### 第四期：交互统一

- 顶部栏同类"选一个值"的控件采用同一交互形态与同一套无障碍语义。
- 主题选择在顶部栏与设置页共用同一份选项数据与同一套样式来源，尺寸差异通过修饰类表达；`documentElement` 主题写入收敛到单一处。

## Acceptance Criteria

### 每期共通

- [ ] 该期改动前后，受影响元素在 1440 / 1024 / 768 / 390 / 375px 五个宽度下的关键计算样式（高度、内外边距、圆角、边框、背景、字号、字重）逐项对比一致；第二期仅允许 requirements 明确要求的 select `appearance`、自绘箭头背景和统一 `padding-right` 差异，第一、第三期差异集合为空，第四期的差异必须逐项在设计文档中列明预期。
- [ ] 无文档级水平溢出；顶部栏在移动端仍保持自身内容高度（不得回归 `08-11-fix-mobile-monitor-summary-clipping` 的缺陷）。
- [ ] 移动端所有交互控件的可点区域不小于 44px。
- [ ] `npm --prefix web run lint`、`npm --prefix web run build`、`go test ./...`、`go vet ./...`、`git diff --check` 通过。
- [ ] 本地运行验证：`/healthz` 正常，构建后的 CSS 含该期改动。
- [ ] 已按部署门禁部署到 `10.0.0.6`，替换前保留二进制、配置、SQLite 数据与服务单元的时间戳备份，并完成远程服务、健康接口与资源哈希验证。
- [ ] 等待用户在部署实例上人工验收确认后再提交该期代码。

### 第一期

- [ ] 交互控件高度的字面值显著下降（74 条规则中落在四个档位上的 55 条全部改为令牌引用），剩余字面值均有记录在案的保留理由。
- [ ] 高频角色间距（标签贴合 / 行内 / 列表行 / 区块 / 页面壳 / 药丸内边距 / 表格单元格）收敛为令牌引用，其余间距字面值均登记在设计文档账本中。
- [ ] 焦点环的 `outline-width` / `outline-color` / `outline-offset` 字面值全部改为令牌引用，`outline-offset` 的四种取值各有语义命名与盒模型理由注释。
- [ ] 断点审计完成；安全项已统一，不能在零视觉变化约束下统一的项已有计算样式或级联证据并登记到第五期。
- [ ] `index.css` 中不再有违反类型比例尺注释的硬编码字号，或注释已更新为与实际一致。

### 第二期

- [ ] 药丸外观属性（边框、背景、圆角、过渡）不再在多处重复声明，改为单一来源。
- [ ] 组件规则中不再存在会压过单类工具类的"类 + 标签"选择器。
- [ ] 每个 `select` 均有一致的箭头留白与外观；`.data-toolbar select` 的箭头不再无留白。

### 第三期

- [ ] 表单区域的 `!important` 数量降为 0，或剩余项逐条有说明。
- [ ] 设置页表单控件、勾选框、可选卡片（接口选项、主题选项）的渲染与改动前一致。

### 第四期

- [ ] 顶部栏的主题与自动刷新采用同一交互形态，键盘操作与屏幕阅读器语义一致。
- [ ] 主题选项数据与样式来源唯一，顶部栏与设置页表现符合各自尺寸预期。
- [ ] 自动刷新的可选值集合与生效行为与改动前完全一致。

## Notes

- 视觉不变的证明方式沿用 `08-11-fix-mobile-monitor-summary-clipping` 的做法：复制真实 `index.css` + 真实 DOM 结构的静态 harness + headless Chrome 计算样式与几何测量。macOS 上 headless Chrome 有 ~500px 最小窗口宽度，测窄屏须强制容器宽度；本机没有 `timeout` 命令，且 Chrome 进程会驻留需显式终止。
- 清点与批量替换等重复劳动交由 codex 执行，Claude 负责定标、审 diff 与把守部署门禁。
- 现状清点结果见 `/tmp/rosboard-ui-tokens/inventory.md`（不入库）；比例尺决策与每期范围见 `design.md`。
