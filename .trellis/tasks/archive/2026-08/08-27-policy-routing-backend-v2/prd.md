# 策略路由后端 V2 精简重构 PRD

## 1. 状态与目标

- 状态：实现、自动化验证、`10.0.0.6` 备份部署和用户人工验收均已完成。
- 父任务：`08-20-policy-routing`。
- 本任务只重构策略路由后端；已敲定的前端交互是需求边界，不重新设计页面。
- 目标：用可读、可测试、可重试的最小后端，完成“保存草稿 → 预览差异 → 应用 RouterOS → 展示结果”。

## 2. 核心原则

1. 只实现当前前端实际需要的功能，不为假设场景建设框架。
2. 配置编辑不直接写 RouterOS；只有用户确认应用后才写入。
3. RouterOS 应用采用幂等协调：扫描实际状态，计算差异，重复执行最终收敛。
4. 只修改带本 rosboard 安装、设备和逻辑对象身份的受管对象；其他对象只读。
5. 失败后停止并保留错误，下次重新扫描并重试；不实现通用回滚、断点续跑和人工决策状态机。
6. 代码行数不是目标；最少职责和可验证行为才是目标。

## 3. 必须支持的前端工作流

### 3.1 查询与配置

- 读取 overview 和 RouterOS WAN/LAN discovery。
- 策略路由直接复用设备的 RouterOS REST 账号，不再保留独立策略账号、策略账号 provisioning、step-up 或 cleanup 能力。
- 设备账号缺少 RouterOS `write` 权限时，策略页明确阻止写操作并引导用户到设备管理更换账号。
- 保存设备级“策略流量入口”，所有出口策略共享。
- discovery 隐藏 RouterOS 内置 `all / none / dynamic / static`，展示用户 interface list、Bridge、VLAN、WireGuard、其他固定 VPN/隧道接口及承担三层 LAN 的独立物理接口；不存在的名称不可手工添加。
- 存在 `LAN` interface list 时默认选中；已被所选列表覆盖的具体接口仍可见但不重复选择。动态 L2TP/SSTP/OpenVPN 通过现有专用 interface list（如 `VPN-LAN`）纳入，rosboard 不配置 VPN 本身。
- 创建、编辑、启停和删除出口策略，支持前端现有 IPv4/IPv6、共享/专用列表、路由及失败模式字段。
- 编辑继续预览差异后应用；启停和删除确认后直接生成并执行内部计划，不再要求用户进入“应用设置”。
- 停用只禁用该策略拥有的 RouterOS 激活、DNS、路由和 NAT 规则；共享入口、其他策略仍引用的标记数据和外部路由表保持不变。
- 删除只清理该策略拥有的对象；清理成功后物理删除 tombstone，失败时保留可重试状态。
- 删除设备最后一条策略后，同时清理不再被任何策略引用的 rosboard 聚合策略流量入口 interface list 及成员；设备保存的入口选择仍保留，供以后新建策略复用。
- RouterOS 受管对象 comment 在稳定所有权标识后追加策略名称、域名列表名称和用途；专用标记列表名使用域名列表名称关键字加短稳定后缀，增强人工排查可读性但不改变精确所有权边界。
- 新建策略默认使用“每个域名列表专用标记列表”；编辑既有策略时保持其原模式。
- 创建、编辑、解绑和删除 URL/上传域名来源。
- URL/上传内容先预览解析，再保存待应用版本；规则可分页、搜索和按类型过滤。
- URL 来源按已保存 schedule 定时刷新为待应用版本，但不自动写 RouterOS。

### 3.2 计划与应用

- `POST /plans` 返回当前前端 `ChangePlanView` 可直接消费的计划结构。
- 计划只包含归一化后的 `create / patch / move / delete` 操作、摘要、阻断和必要确认。
- `POST /plans/{id}/apply` 依赖现有登录会话授权，校验草稿 revision 和 RouterOS 实际状态指纹后启动应用，不再重复要求管理员密码。
- overview 返回最小活动任务和最近结果；前端无需恢复、回滚或取消编排。
- 成功后提升待应用来源版本、清除已完成 tombstone，并更新 applied 状态；失败时保留草稿和待应用版本。

## 4. 明确不做

- 不可变计划仓库、execution group、依赖 DAG、write-ahead mutation journal。
- 通用 RouterOS 备份/恢复、自动补偿、部分地址族提交、任务 resume/rollback/needs_decision。
- ownership hash、自动漂移修复、DNS 语义探针、计数器探针、route runtime 证明、Move/DNS capability probe。
- 手工对象接管、其他 rosboard 实例强制接管、复杂共享对象字段归属。
- 审计历史、备份下载和未接入当前页面的高级运维入口。
- 创建或修改 PPPoE、DHCP Client、WireGuard、WAN 地址、BGP、OSPF、VRF 等接入配置。
- 定时刷新后自动应用 RouterOS。

## 5. 必须保留的低成本安全边界

- 现有面板登录认证、请求体和上传大小限制；策略写操作使用设备 RouterOS 账号且必须具备 `write` 权限。
- HTTPS 来源的 SSRF 防护、重定向检查、DNS/IP 固定和内容限制。
- 每设备同一时刻只允许一个应用任务；不同设备互不阻塞。
- 精确受管身份；禁止按宽泛 `rosboard:` 前缀删除对象。
- 新建/更新和激活优先，失效受管对象最后清理；禁止先清空再重建。
- 配置 revision 与实际状态指纹过期检查。

## 6. 验收标准

- [x] 当前策略路由页面无需结构性重写即可完成查询、配置、来源预览、计划预览和应用。
- [x] “策略流量入口”只展示实机发现候选、默认选择 `LAN`，多选列表/接口由 rosboard 受管聚合列表统一供 mangle 引用，WireGuard 入站流量可进入策略路由。
- [x] 单 IPv4 出口纵向链路在 fake RouterOS 和 `10.0.0.99` 上通过。
- [x] 前端已经提供的 IPv6、多出口、共享/专用列表、启停和待删除流程通过。
- [x] 停用/启用立即同步 RouterOS，停用只设置本策略规则 `disabled`；删除确认后立即清理并不再显示“请点击应用设置”。
- [x] 多策略共享标记名称或复用外部 routing table 时，停用/删除一条策略不影响其他策略或外部对象。
- [x] 策略运行时复用设备账号；只读老账号得到明确引导，设备管理可查看账号权限、编辑凭据并重新生成一键接入脚本。
- [x] 删除最后一条策略后，受管策略流量入口 interface list 与成员被清理；仍有策略时保持。
- [x] 新建策略默认专用标记列表；受管 mangle、route、DNS static 等 comment 可读且名称变化后仍按稳定身份识别、更新和清理。
- [x] 计划展示的操作与应用时实际执行的操作一致；草稿或实际状态变化会拒绝旧计划。
- [x] 外部对象、手工对象和其他安装实例对象在成功、失败及重试路径中均不被修改或删除。
- [x] 任意一步注入失败后任务进入 failed；再次应用能从实际状态重新计算并收敛，无需恢复状态机。
- [x] 同设备并发应用被拒绝；不同设备可以独立执行。
- [x] 成功后来源版本和 tombstone 正确提交；失败后不会把待应用版本标成 active。
- [x] 后端单元/契约/集成测试、`go test ./...`、`go vet ./...`、前端 build/typecheck 和 `git diff --check` 通过。
- [x] 已完成本地验证、`10.0.0.6` NAS 备份部署和用户人工验收门禁。
