# 改善终端列表与单终端连接详情

## 背景

终端列表把设备名称单列、IP 与 MAC 混在另一列，信息层级不清晰。单终端连接详情又把来源地址和端口合并展示，并使用归一化后的终端端点，无法直接查看 RouterOS 原始 `src-address / src-port`。

讨论中提到连接表未来可以复用于总体流表，但用户随后明确本次不需要独立全局流表页面、菜单或 API。本任务只修改全部终端列表和现有单终端连接详情。

## 已确认需求

### 全部终端列表

- 第一列显示设备身份：设备名称为主，MAC 地址为第二行辅助信息。
- IP 独立成列。
- “全部终端”范围中，IPv4 主地址显示在第一行，IPv6 主地址显示在第二行。
- IPv4、IPv6 子范围只展示对应地址族，并保留现有数字地址升序默认排序。

### 单终端连接详情

- 来源 IP 与来源端口拆成两列，分别支持筛选和排序。
- 来源字段严格显示 RouterOS 原始 `src-address / src-port`。
- 目的字段严格显示同一原始方向的 `dst-address / dst-port`。
- 当前速率和累计流量继续以该终端视角显示“上传 / 下载”，沿用现有 B/KB/MB 自动换算。
- 保留地址族、应用、协议、外网地址、路由表、下一跳网关、状态、全局搜索、清除和移动端操作。
- RouterOS 自身详情继续显示连接状态列；普通终端不显示。

## 明确不做

- 不新增独立“流表”菜单或页面。
- 不新增全局 `/api/connections`。
- 不展示无法归属终端的全局 conntrack 行。
- 不增加分页、历史流表、DPI 或连接终止操作。

## 验收标准

- [ ] 全部终端列表第一列为“设备名称 + 第二行 MAC”，IP 列在全部范围为“IPv4 第一行 + IPv6 第二行”。
- [ ] IPv4 / IPv6 子列表只显示对应地址族，默认地址排序无回归。
- [ ] 导航中不存在新增的独立“流表”。
- [ ] 单终端连接详情的来源 IP、来源端口为独立列，可分别筛选和排序。
- [ ] 来源与目的四元组对应 RouterOS 原始 `src-* / dst-*`。
- [ ] 速率和累计流量仍按该终端显示上传/下载并沿用现有单位。
- [ ] 桌面端与 375px 移动端无页面级横向溢出。
- [ ] 自动化检查通过，部署到 `10.0.0.6` 后等待用户人工视觉验收再提交。
