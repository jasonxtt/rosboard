# 实施计划

1. 增加当前构成数据契约
   - 在 Go 与 TypeScript `Overview` 类型中增加终端状态和连接协议三类计数。
   - 在完整刷新与终端刷新路径中从相同批次原始数据计算并写入计数。
   - 验证：后端单元测试覆盖范围排除、三种终端状态、协议大小写/未知值及合计不变量。

2. 扩展指标卡片展示
   - 为 `MetricCard` 增加可选标题图例和构成分段数据，保留 CPU/内存现有进度条路径。
   - 新增三段横线及其数量/占比悬浮详情；处理字段缺失、总数为零和零宽分段。
   - 调整卡片标题行与深浅主题样式，不改变底部平均/峰值。

3. 增加四张迷你折线悬浮详情
   - 向迷你折线传递时间戳、指标名和格式化规则。
   - 实现最近点选择、指示线/点、时间与数值浮层、边缘定位及离开隐藏。
   - 保持原 SVG 尺寸、折线绘制和卡片宽度收缩行为。

4. 质量验证
   - 运行 `gofmt`、`go test ./...`、`npm --prefix web run lint`、`npm --prefix web run build` 和 `npm --prefix web audit --audit-level=high`。
   - 以嵌入式 Go 构建启动本地页面，检查四张卡片的悬浮值、横线分段悬浮、深浅主题与持续刷新无控制台错误。
   - 在 375px、768px、1024px、1440px 检查标题图例不覆盖、卡片高度与底部统计不回归、页面无横向溢出。

5. 发布到 `10.0.0.6`
   - 只读确认远端架构、systemd 单元、二进制/配置/数据路径与发布前健康状态。
   - 构建 Linux amd64 二进制并传输到独立临时路径；停止服务后按同一时间戳备份旧二进制、配置和 SQLite 文件，再原子安装新程序并启动服务。
   - 验证 systemd active、`/api/health`、Dashboard 两组构成字段及其合计不变量、时间戳继续推进和新嵌入式资源哈希；启动失败则恢复旧二进制。

## 风险文件与回滚点

- `internal/model/types.go`：API 契约；若计数不变量失败，先回滚字段写入而不是伪造前端比例。
- `internal/service/monitor.go`：两个刷新路径必须同步更新。
- `web/src/App.tsx`：保持改动集中在 Overview 数据准备、`MetricCard` 和 `MiniSparkline`。
- `web/src/index.css`：只调整概览指标卡片相关选择器，避免影响详情页图表。
