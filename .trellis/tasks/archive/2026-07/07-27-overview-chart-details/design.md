# 系统概览图表语义与悬浮详情设计

## 1. 边界与职责

- 后端只负责提供当前构成的可靠计数：终端状态三类与连接协议三类。
- 现有 `LoadSample` 继续负责四张迷你折线的历史时间点，不修改存储结构和历史接口。
- 前端 `MetricCard` 负责卡片标题、图例、折线、当前构成横线及底部平均/峰值的组合；实时流量 ECharts 组件不修改。

## 2. 数据契约

在 `Overview` 中增加两个嵌套对象：

```text
terminalStateCounts: { online, inactive, offline }
connectionProtocolCounts: { tcp, udp, other }
```

- 终端状态计数沿用首页在线终端的 LAN 范围：排除路由器自身、WAN/loopback 和已选流量出口，但不再以 `online` 作为范围过滤条件。`online` 必须与 `connectedDeviceCount` 一致。
- 连接协议计数直接遍历 RouterOS IPv4 与 IPv6 原始连接，按规范化后的协议名归入 `tcp`、`udp` 或 `other`。三项之和必须与 `connectionCount` 一致。
- 完整刷新和终端刷新都同时更新上述当前计数，避免卡片总数与分段构成来自不同采集批次。
- 不从现有 `protocols` 应用分类结果反推协议构成，也不改变该列表的聚合行为。

## 3. 卡片布局

- 卡片标题由单一标题改为左右同行：左侧原标题，右侧可选极简图例。
- 终端图例固定为“在线 / 未活跃 / 离线”；连接图例固定为“TCP / UDP / 其他”。每项只有色点与名称，不显示数量。
- 主数值、迷你折线、比例横线和底部“平均 / 峰值”保持原顺序。图例使用标题行已有高度，卡片高度不增加。
- CPU/内存保留现有单色进度横线且不显示图例；终端/连接使用三段横线。
- 终端颜色使用当前紫色为在线主色，未活跃使用低饱和警示色，离线使用中性灰；连接使用当前橙色为 TCP 主色，UDP 使用可区分的蓝色，其他使用中性灰。深色主题提供对应 token。

## 4. 交互

### 4.1 迷你折线

- `MetricCard` 向 `MiniSparkline` 传递相同长度的数值与时间戳，以及指标名称和格式化函数。
- 指针在 SVG 内移动时，按横向位置选择最近采样点，显示虚线指示线、当前点和深色浮层。
- 浮层显示“时间：HH:mm:ss”和一行指标值；CPU/内存带 `%`，终端带“台”，连接使用本地化整数。
- 浮层在图表左右边缘自动换向或限制位置，离开图表后消失。单点数据仍可悬浮。

### 4.2 构成横线

- 横线按当前计数比例分配宽度；每个非零分段可悬浮或键盘聚焦。
- 浮层显示分类名称、当前数量和一位小数占比。
- 总数为零时显示中性空轨道和可读的“暂无数据”语义；零值分类保留标题图例但不生成零宽交互目标。

### 4.3 一致性与可访问性

- 两类浮层共用同一 CSS 视觉规则，与实时流量 tooltip 的深色背景、边框、字号接近。
- 标题图例、横线容器和迷你折线提供完整 `aria-label`；颜色只做辅助，不是唯一语义来源。

## 5. 兼容、风险与回滚

- 新增 JSON 字段对旧消费者是向后兼容的；前端对字段缺失使用零值对象，避免刷新部署窗口报错。
- 最大视觉风险是窄卡片标题图例换行或挤压。图例保持短标签、禁止换行，并在 375px、768px、1024px、1440px 检查布局。
- 最大数据风险是计数范围不一致。后端单元测试必须验证终端 `online == connectedDeviceCount`，以及协议三项之和等于原始连接总数。
- 回滚只需移除新增 Overview 字段和前端可选图例/分段 props；历史数据与数据库无需迁移。
