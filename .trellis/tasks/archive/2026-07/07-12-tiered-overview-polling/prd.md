# 分层刷新系统概览采集

## Goal

让系统概览的实时流量、CPU 和内存默认每秒更新，同时把 RouterOS 高成本数据拆到较慢周期，避免把现有全量采集直接放大五倍。

## Background

- 当前后端每 5 秒串行执行一次全量采集，包括资源、地址、邻居、IPv4/IPv6 conntrack、策略、路由和逐接口流量；`/api/dashboard` 只读取内存快照。
- 当前实例有 8 个接口、约 66 个终端和约 388 条连接，完整 dashboard JSON 约 80 KB。
- 用户接受分层方案并授权规划完成后直接实施。

## Requirements

- R1：新增默认 1 秒的轻量采集，只读取 CPU/内存和配置的概览流量接口，并更新内存快照及实时曲线。
- R2：终端在线状态和连接数按默认 3 秒采集；不得为了它们每秒重读策略和路由。
- R3：接口完整状态、系统状态、告警、DHCP/ARP/IPv6 邻居、策略和路由按默认 10 秒完成全量刷新。
- R4：三个周期可通过配置修改，校验为正整数；示例配置和本地配置使用 1/3/10 秒。
- R5：系统概览默认选择“1 秒刷新”。概览页面每秒读取轻量实时接口，完整 dashboard 每 3 秒读取一次；其他页面保持现有全量响应契约。
- R6：不同采集层不得并发写坏快照或重复堆积；采集失败保留最后一次有效数据并继续后续周期。
- R7：历史落库避免无意义膨胀：实时图表允许 1 秒采样，清理操作不得每秒执行。

## Acceptance Criteria

- [x] AC1：默认配置运行时，CPU、内存、上传、下载和实时图表约每秒更新。
- [x] AC2：终端数量和连接数最多约 3 秒更新一次；策略、路由、完整接口状态和系统告警最多约 10 秒更新一次。
- [x] AC3：新增轻量 API 不返回终端、连接明细、策略或路由，并由前端默认每秒调用。
- [x] AC4：完整 `/api/dashboard` 不再由概览页面每秒下载，浏览器无请求重叠、控制台错误或页面闪烁。
- [x] AC5：终端和全量慢轮次互不重叠；独立实时轮次不会被慢轮次阻塞，且慢轮次不会覆盖更新的实时字段。
- [x] AC6：Go 测试、前端 lint/build、安全审计和浏览器验证通过；局域网地址返回 HTTP 200。

## Out of Scope

- 不改变终端在线判定算法。
- 不引入 WebSocket、SSE、Redis 或新的外部服务。
- 不让每个浏览器请求直接触发 RouterOS 采集。
