# 优化自动识别与高级设置排版

## Goal

让设备管理中的“自动识别与高级设置”更容易扫描、理解和操作：用户先看清系统自动识别了什么，只有遇到特殊拓扑时才进入覆盖配置，同时避免展开后形成超长、缺乏层级的表单。

## Background

- 当前实现把自动识别结果和高级覆盖表单嵌套在同一个 `<details>` 中；高级覆盖再次使用内层 `<details>`，见 `web/src/App.tsx:1337-1370`。
- 自动识别结果依次展示流量采集接口、LAN 接口、IPv4 网段和 IPv6 网段，但不同区块共享相近的灰底、细边框和小字号，视觉层级不足，见 `web/src/index.css:442-451`。
- 高级覆盖展开后，6 个 textarea 全部纵向占满容器宽度，使页面高度显著增加；“终端范围覆盖”仅使用普通段落，不能形成稳定的二级分组。
- 当前表单只有一个“保存设备”动作；高级覆盖不是独立保存流程。

## Requirements

- R1. “自动识别范围”作为独立折叠卡，默认收起；标题与状态摘要分层展示，不再把“高级设置”混入同一标题。
- R2. 自动识别结果按“上网流量”和“本地终端”分为两个可快速扫描的区块，并清楚区分接口、IPv4 网段和 IPv6 网段。
- R3. 识别依据属于辅助信息，默认弱化展示；名称、运行状态、范围数量等核心结果保持主视觉优先级。
- R4. “高级覆盖设置”默认收起，只在用户明确展开后显示，并明确提示“留空即使用自动识别”。
- R5. 高级覆盖保留在当前设备表单内，但作为与“自动识别范围”平级的独立折叠卡；继续复用设备表单的统一保存动作，不引入弹窗、侧边栏或独立保存语义。
- R6. 高级覆盖按“流量采集覆盖”和“终端范围覆盖”分组；纳入/排除字段在桌面端成对并排，在窄屏单列排列。
- R7. 避免为单项内容制造空白大卡片；IPv6 等结果较少时，布局仍保持紧凑和平衡。
- R8. 保持现有自动识别、覆盖字段、保存语义和后端数据契约不变。
- R9. 可交互标题应有清晰的展开状态、点击区域和键盘焦点反馈。

## Acceptance Criteria

- [x] 页面首次显示时，“自动识别范围”和“高级覆盖设置”均为收起状态；自动识别标题直接展示上网线路、LAN 接口和网段数量。
- [x] 展开自动识别后，用户可在一次扫描中区分“上网流量”与“本地终端”两类结果。
- [x] 展开高级覆盖后，6 个字段形成两个语义分组，桌面端不再全部单列占满整行。
- [x] 桌面端 1440px 附近页面高度明显短于当前实现；375px 下无横向滚动且字段保持可读。
- [x] 自动识别和覆盖数据的提交内容与当前实现一致。
- [x] 键盘可操作折叠控件，焦点样式可见，输入控件在移动端满足至少 44px 的操作高度。

## Out of Scope

- 修改 RouterOS 自动识别算法、识别理由或 API 返回结构。
- 增加新的覆盖规则、独立保存接口或自动保存行为。
- 重做整个设备管理页面或全局视觉主题。
