# Clarify RouterOS self conntrack UI

## Goal

Rename misleading RouterOS self connection wording, expose seen-reply/assured conntrack state, rebuild, and launch LAN-accessible UI.

## Requirements

- Rename the synthetic RouterOS terminal so it clearly represents RouterOS-owned conntrack rows, not only established traffic generated by the router.
- Preserve Winbox parity by retaining all `/ipv6 firewall connection` rows, including rows without a reply.
- Expose `seen-reply` and `assured` on terminal connection API objects and show their Winbox `S`/`A` meaning in the connection table.
- For the RouterOS synthetic terminal, use `conntrack`/tracking-entry wording in list and detail summaries instead of generic effective-connection wording.
- Keep normal LAN terminal wording and family scoping unchanged.
- Build the embedded frontend and Go binary, then launch on `0.0.0.0:8080` for LAN review when RouterOS credentials are available.

## Acceptance Criteria

- [x] The RouterOS row is named `RouterOS 本机连接跟踪` or an equally explicit label.
- [x] RouterOS detail labels total rows as tracking entries and separates replied/unreplied counts.
- [x] Connection rows display Winbox-compatible `S` and `A` flags with clear Chinese status text.
- [x] The captured unreplied UDP/58680 rows display as `未见回包`, not `已连接`.
- [x] LAN terminal list/detail behavior is unchanged.
- [x] Go tests/race/vet/build, frontend lint/build, API checks, and browser checks pass.
- [x] The built UI is reachable from both localhost and the Mac LAN address on port 8080, or the exact missing runtime credential blocker is reported.
