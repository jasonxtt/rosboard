# 重塑 Rosboard 前端 UI

## Goal

在不改变 Rosboard 监控语义和后端契约的前提下，重塑前端视觉与交互，使其成为专业、清晰、适合日常运维的 RouterOS 监控控制台。

## Background

- 当前前端是 React 19 + TypeScript + Vite，无第三方组件库或状态管理库。
- 当前产品是只读 RouterOS 运维监控台，已有系统概览、线路、终端、负载、协议、策略和路由等页面。
- 现有信息架构采用桌面端两级/三级侧边导航，页面以数据表格、指标和趋势图为主。
- 前端主要集中在 `web/src/App.tsx` 和 `web/src/index.css`；本任务需要同时处理视觉系统、响应式和必要的组件边界。
- 既有功能约束包括终端默认只显示在线设备、工具栏控件高度 34px，以及文本型按钮必须保留键盘焦点环。
- `ui-ux-pro-max` 对此产品类型的初始建议是 data-dense operations dashboard：中性或深色基底、清晰的状态色、高信息密度、完整明暗模式能力和 WCAG AA 可访问性。
- 用户已批准概念图所示的总体方向：深海军蓝侧边栏、浅灰白工作区、蓝色主色、克制的状态色、紧凑指标卡，以及以图表和表格为核心的专业运维界面。
- 本轮只实现浅色主题，不提供深色模式切换；颜色仍须通过语义化设计令牌定义，为后续深色主题保留清晰扩展边界。
- 响应式定位为桌面和平板优先、手机完整可用：桌面保留高密度表格和多栏仪表盘，平板收起侧边栏并减少并排内容，手机使用抽屉导航、单列指标、简化图表以及关键列加行详情的表格表达。
- 保留 `Rosboard` 名称并增加一个确定性的、简洁的 R/网络连接抽象 SVG 标志；同一标志可用于侧边栏品牌区和 favicon，不扩展为完整品牌设计项目。
- 改造包含视觉系统、响应式、组件拆分和交互一致性整理，但默认不改变后端 API、刷新机制、指标语义或监控业务逻辑。

## Requirements

- 保留现有监控能力、只读边界、数据真实性标注和 API 行为。
- 采用用户已确认的现代专业网络运维控制台风格和桌面/平板优先、手机完整可用的响应式定位。
- 建立统一的颜色、排版、间距、圆角、边框、阴影、状态色和动效令牌。
- 本轮只交付浅色主题，不把深色主题及其切换机制纳入验收范围。
- 重构页面层级、导航、指标卡、工具栏、表格、图表、弹窗、空状态、加载和错误反馈，使其视觉一致。
- 保持运维场景所需的信息密度，同时提高扫描效率和重点状态辨识度。
- 提供适配桌面、平板和手机的布局，不再依赖当前 `min-width: 1280px` 的固定桌面宽度。
- 手机端不得通过压缩字号硬塞桌面表格；应优先显示关键列，并让次要字段可从行详情访问。
- 满足键盘导航、焦点可见、文本对比度、非纯颜色表达状态和 reduced-motion 等基本可访问性要求。
- 先把已认可的概念方向落实到系统概览并通过浏览器样板检查，再扩展到全部页面。
- 品牌图标使用项目内 SVG，不依赖生成概念图中的随机图形。
- 将当前集中在 `App.tsx` 的布局、页面和通用 UI 拆分为清晰的前端模块；不为拆分而引入第三方全局状态管理。
- 后端修改仅允许用于修复前端重塑无法绕开的兼容问题，并须保持现有 API 向后兼容；当前规划不包含后端改动。

## Acceptance Criteria

- [x] 用户明确批准概念图所示的最终视觉方向。
- [x] 系统概览的真实浏览器样板与已批准方向一致，并作为其余页面的实现基准。
- [x] 所有现有一级页面和终端详情功能保持可用，监控数据含义不改变。
- [x] 页面在 375、768、1024 和 1440px 视口下无非预期水平滚动，关键操作可达。
- [x] 颜色、排版、间距、控件状态和数据可视化遵循统一设计令牌。
- [x] 键盘焦点、触控目标、对比度、状态表达和 reduced-motion 达到约定的可访问性要求。
- [x] 前端 lint、TypeScript 构建和生产构建通过。
- [x] 使用真实 RouterOS 数据，在浏览器中检查主要页面、终端详情、弹窗、加载、错误和空状态。

## Out of Scope

- 修改 RouterOS 配置或增加新的监控业务能力。
- 无证据地改变现有指标含义、在线判定或统计口径。
- 深色主题和主题切换功能。
