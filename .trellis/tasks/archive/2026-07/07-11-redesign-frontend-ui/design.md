# Rosboard 前端 UI 重塑设计

## Design Summary

在保持现有 RouterOS 只读监控功能和 API 契约不变的前提下，把当前单体 React 页面重构为现代、专业、数据密集但易扫描的网络运维控制台。视觉方向采用用户已批准的概念图：深海军蓝导航、浅灰白工作区、蓝色主操作色，以及仅用于状态表达的绿、黄、红。

## Boundaries

- 仅实现浅色主题；颜色使用语义化 CSS 变量，为未来深色主题保留边界，但本轮无主题切换。
- 不改变 RouterOS 配置、监控口径、数据真实性标签、后端 API 或定时刷新语义。
- 不引入全局状态管理或重量级 UI 组件库。
- 允许增加小型图标依赖；品牌标志与 favicon 使用项目内确定性 SVG。
- `web/src/App.css` 是未被入口引用的 Vite 模板遗留样式，本任务可删除；实际样式入口仍为 `web/src/index.css` 或其拆分后的导入树。

## Information Architecture

保留现有页面集合和分组：

```text
系统概览
状态监控
  线路监控
  终端监控
    全部终端
    IPv4
    IPv6
流量监控
  协议统计
  策略统计
运行监控
  负载历史
  路由 / 分流
```

- 桌面使用固定侧边栏；平板和手机使用可关闭的抽屉导航。
- 顶栏统一承载页面标题、系统状态、更新时间、刷新频率和移动端菜单入口。
- 终端详情继续作为终端监控内部视图，保留返回路径和标签页。
- 本轮不强制引入路由库；现有视图状态可保留，但导航组件应形成将来接入 URL 状态的清晰边界。

## Visual System

### Tokens

- 背景：冷灰白工作区、白色表面、深海军蓝导航。
- 主色：中等饱和蓝，用于选中态、主要按钮、链接和图表主序列。
- 状态色：成功绿、警告琥珀、危险红、信息蓝；所有状态同时使用文本或图标，不只依赖颜色。
- 排版：优先系统中文无衬线字体，数字启用 tabular figures；正文至少 14px，移动端输入正文至少 16px。
- 间距：4px 基础、8px 节奏；桌面维持紧凑数据密度。
- 表面：6–10px 圆角、细冷灰边框、极轻阴影；禁止玻璃拟态、霓虹和装饰性大渐变。
- 动效：150–250ms，仅用于状态和空间关系；遵守 `prefers-reduced-motion`。

### Core Components

- `AppShell`：侧边栏、抽屉、顶栏、内容区和全局通知。
- `BrandMark`：Rosboard SVG 标志与文字组合。
- `SidebarNav`：分组导航、当前项、移动端关闭行为。
- `PageHeader`：标题、说明、系统状态、更新时间与刷新控制。
- `MetricCard`：图标、指标、辅助值、趋势或进度表达。
- `Panel` / `PanelHeader`：统一内容容器。
- `DataToolbar`：搜索、筛选、刷新、计数和分段控制。
- `DataTable`：桌面高密度表格与移动端关键字段/行详情策略。
- `StatusBadge` / `StatusDot`：带文字的语义状态。
- `EmptyState` / `ErrorNotice` / `LoadingState`：统一反馈。
- `Modal` / `Tabs` / `Pagination`：统一交互和键盘行为。
- `TrafficChart` / `MetricHistory`：共享颜色、网格、图例和数值格式。

## Source Boundaries

目标结构保持简单，不做过度抽象：

```text
web/src/
  app/             应用外壳、导航配置和顶层状态
  components/      至少两处复用的通用 UI
  pages/           overview/interfaces/terminals/monitoring 页面
  lib/             API 类型、格式化和排序等纯函数
  styles/          tokens、base、components、responsive
  assets/          品牌 SVG
```

- API 类型和格式化函数从 `App.tsx` 移出，页面只保留自身交互状态。
- 顶层 `App` 继续负责仪表盘刷新、选中视图和跨页面状态，避免同时引入新的状态架构。
- 只在真实复用或独立交互边界存在时抽组件；一次性小块保留在所属页面。

## Responsive Behavior

- `>= 1200px`：固定侧边栏，多栏概览和高密度表格。
- `768–1199px`：抽屉或窄导航，指标卡两列，内容区减少并排面板。
- `< 768px`：抽屉导航、单列内容、紧凑顶栏、触控目标至少 44px。
- 手机表格显示关键列；次要字段通过可展开行详情访问，不使用小于可读阈值的字体硬塞列。
- 图表保持宽高比、缩减轴标签密度，禁止页面级非预期横向滚动。
- 对确实需要对照的超宽连接明细，可在明确标识的表格容器内局部横向滚动，不能让整个页面滚动。

## Accessibility and Interaction

- 所有图标按钮有可访问名称；所有输入有可见标签或等价 `aria-label`。
- 键盘焦点环始终可见，表格操作、标签页、抽屉和弹窗可用键盘完成。
- 弹窗打开时管理焦点，Escape 可关闭，关闭后焦点返回触发点。
- 普通文本对比度至少 4.5:1；状态不能只靠颜色区分。
- 加载超过约 300ms 使用骨架或明确进度；刷新失败保留最后一次有效数据并显示非阻塞错误。

## Compatibility and Rollback

- Vite 输出仍写入 `internal/ui/dist`，保持 Go 嵌入式前端构建路径不变。
- API 请求路径、请求频率、终端筛选默认值和备注保存行为保持不变。
- 按垂直切片实施，每个阶段保持 `npm run lint`、`npm run build` 和 Go 测试通过。
- 视觉重构通过源文件提交整体回滚；不涉及数据库迁移或线上数据回滚。

## Trade-offs

- 只做浅色主题可缩小本轮验收面；语义令牌避免未来新增深色主题时重写组件。
- 组件拆分会扩大文件数量，但显著降低当前 1316 行 `App.tsx` 和 757 行单样式表的维护成本。
- 移动端采用关键字段加详情，而不是复制桌面全部列，以换取可读性和可操作性。
- 不立即引入路由库可降低行为回归风险；URL 导航属于后续独立改进。
