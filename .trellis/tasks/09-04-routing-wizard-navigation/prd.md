# 策略向导导航与预览优化

## Goal

优化新增策略向导的跨步骤查看、锁定编辑、完成后回跳修改与预览刷新流程；依据项目审核者方案实施，保持后端提案/计划/应用边界不变。

## Requirements

- 在新增策略向导中，步骤标题 1–4 始终可点击查看；尚未通过前置步骤的后续步骤只读，不能修改任何表单值或触发创建/保存操作。
- “下一步”仍是正式解锁门槛：策略与来源校验通过后解锁访问目标；至少选择一个访问目标后解锁出口；出口校验通过后生成预览计划。
- 已存在策略打开编辑时，步骤 1–3 默认可编辑；步骤 4 在首次点击时按当前草稿执行完整校验并生成预览。
- 进入后续步骤查看时不得写入后端 canonical 配置；点击“预览并应用”标题只允许执行校验和生成/刷新计划，不得直接应用。
- 预览后返回前面已完成的步骤修改草稿，再次点击“预览并应用”应自动校验并只生成一份与最新草稿对应的新预览，不需要重复点击多个“下一步”。未修改草稿时复用仍然有效的预览。
- 生成期间阻止重复生成及导航；应用期间阻止步骤导航、关闭和重复应用。
- 失效预览不得被展示或应用；生成失败时保留草稿和下游选择，并定位到第一个校验失败的步骤。
- 不改变后端 API、提案只读边界、应用接口和非本向导功能。

## Acceptance Criteria

- [ ] 新增策略初始状态只有步骤 1 可编辑；点击步骤 2/3 可查看禁用表单，点击步骤 4 显示只读占位且不产生 `/plans` 请求。
- [ ] 步骤 1 校验失败时不能前进；步骤 1 通过后可编辑步骤 2；步骤 2 未选择目标时不能解锁步骤 3。
- [ ] 出口有效后生成预览；生成请求成功后步骤 4 显示预览。
- [ ] 预览未修改时从任一步骤返回步骤 4 不重复生成；修改草稿后点击步骤 4 自动刷新预览。
- [ ] 修改后校验失败不生成请求，回到首个失败步骤并显示具体错误；下游选择不被静默清除。
- [ ] 预览、导航、返回和编辑过程没有 canonical 写入；只有预览中的明确应用动作调用应用接口。
- [ ] `npm --prefix web run lint`、`npm --prefix web run build` 和 `git diff --check` 通过；变更保持在向导相关前端文件和本任务文档内。
