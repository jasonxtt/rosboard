# RouterOS 域名访问控制与时长配额

## Goal

在不引入旁路网关或第三方应用识别设备的前提下，复用 rosboard
现有终端、域名/IP 列表、终端本地网络范围和 RouterOS 写入能力，为一组终端提供低心智负担的访问控制；
规则可控制整个互联网或一组指定来源，先验证可靠阻断，再扩展固定时段，最后实现规则组共享的每日累计使用时长配额。

## Requirements

- RouterOS 是实际执行面；rosboard 通过现有设备凭据下发、校验和回收受管对象。
- 访问控制按 RouterOS 设备独立配置，引用当前 RouterOS 设备自己的终端身份和域名列表。
- 所有已纳管 RouterOS 都具备相同的访问控制能力；`unicom`、`cmcc` 不存在产品级主从或首期限定。
- 同一物理终端被多台 RouterOS 观察到时，各设备上的规则仍是两个独立配置，不自动复制、合并或联动。
- 一条逻辑访问规则支持选择一个或多个终端；用户默认只选择“设备”，不要求理解 MAC/IP 绑定方式。
- 有可靠 MAC 身份的终端默认“自动跟随设备地址”：rosboard 以稳定设备身份为锚点同步当前 IPv4/IPv6；无可靠 MAC 或用户在高级设置中明确选择时，允许固定精确 IP。
- IP 固定绑定不因后续终端观测或地址复用而自动迁移，界面必须明确提示误绑定风险并允许用户重新选择地址。
- 自动跟随成员暂时离线或无法解析时不得阻断本设备其他访问规则的同步：已成功应用且当前没有相反身份事实的地址投影保持不变并标记 degraded；发现地址已归属其他终端时必须移除错误投影，等待该成员重新解析。
- 第一版不劫持或重定向终端 DNS，不额外阻断外部 DNS、DoT、DoH、VPN、代理或硬编码 IP。
- 域名控制仅对 RouterOS 已通过自身 DNS Static/address-list 掌握的目的地址生效；产品必须明确展示这是可绕过的尽力控制，而非不可规避的家长控制。
- 每日配额按“网络活跃时间”累计，不按首次访问后的连续墙钟时间倒计时，也不宣称等同于屏幕使用时间。
- 多终端逻辑规则使用一个共享配额池：所有成员的有效活跃时间累计到同一个 `(device, rule, local_date)` 账本；例如两台设备同时有效活跃 10 分钟，合计消耗 20 分钟共享额度。
- RouterOS 受管规则计数器是配额计量源；rosboard 默认每 10 秒批量读取一次当前设备的受管 IPv4/IPv6 规则计数。
- 一个采样窗口内双向合计至少增加 4 KiB 或 12 个包时视为有效活跃，过滤低频 keepalive；有效活跃后的最长 30 秒无流量间隔仍并入同一活跃会话，超过后暂停累计。
- 单次采样计入的时间必须限制在正常采样间隔范围内；rosboard 停机、网络中断或长时间调度延迟不得被补算为活跃时间。
- 每日账本使用 RouterOS 本地日期和时区；达到配额后最迟在下一个 10 秒采样周期内启用阻断。
- RouterOS 重启、规则重建或计数器回退只建立新基线，不清空当天已经持久化的累计时间，也不把回退误算成新流量。
- rosboard 离线或无法读取 RouterOS 时不补算配额、不主动切换当前允许状态；RouterOS 上已经启用的阻断和原生固定时段规则继续执行。
- 恢复连接后重新建立计数基线，并在当日账本与 UI 中标记未观测区间；未观测时间不计入已用时长。
- 阻断使用 RouterOS 官方 firewall filter action：TCP 使用 `action=reject reject-with=tcp-reset`，UDP 和其他协议使用 `action=drop`。
- 不尝试把 HTTPS 重定向到本地说明页；阻断原因、今日用量和恢复时间只在 rosboard 管理界面展示。
- 应用前通过 RouterOS 能力读取确认 IPv4/IPv6 filter 支持所需 action 和 matcher；能力不可证明时阻止计划，不猜测下发。
- 固定时段统一表达为“允许访问窗口”：未设置窗口表示全天允许，设置后窗口外阻断。
- 允许窗口按 RouterOS 本地星期和时间执行；跨午夜窗口由 rosboard 拆分为相邻两天的 RouterOS `time`/`days` 规则。
- 多个重叠或相邻窗口在生成期望状态前合并；每日活跃配额只在允许窗口内累计，窗口外流量不扣除配额。
- 管理员可执行“临时放行至 RouterOS 本地当天结束”；该操作不修改策略、不清零累计用量，到本地午夜自动失效。
- 管理员可显式重置某策略的当日累计用量；重置后立即按当前允许窗口和新用量重新计算 RouterOS 阻断状态。
- 临时放行和重置用量都要求确认，并记录管理员、RouterOS 设备、策略、操作前后状态和准确时间。
- 同一个域名或 IP 来源必须能在同一 RouterOS 设备内同时被策略路由和访问控制引用，不能要求用户复制来源或二选一。
- 每个来源在 RouterOS 中使用稳定的来源级 address-list；多个来源仍可共享同一出口、connection mark 和路由表，但不能再把来源成员物理混入一个无法区分来源的共享 address-list。
- 现有 shared address-list 迁移必须保持既有策略路由连续：新来源列表和匹配规则先启用，旧共享列表的兼容匹配最后清理。
- 第一阶段至少支持“一条规则选择多个终端，并禁止访问整个互联网或多个指定域名/IP来源”，不能把策略路由出口当作访问控制开关。
- 访问目标是一级语义：`internet` 表示除当前 RouterOS 已识别的本地终端网络范围之外的网络；`sources` 表示一个或多个来源。`internet` 不能伪装成特殊 source ID 或用户可见的 `0.0.0.0/0` / `::/0` 来源。
- “禁止整个互联网”默认保留本地终端网络访问；IPv4/IPv6 的本地范围复用 rosboard 已计算的 TerminalScope prefixes，能力不可证明时该规则应 degraded/blocked，而不是静默扩大到局域网。
- 第二阶段支持按星期和本地时间设置允许或禁止访问窗口。
- 第三阶段在明确“使用时长”的口径、离线行为和精度后，支持每日累计配额，例如 B 站每天最多使用 1 小时。
- IPv4、IPv6、终端地址变化、DNS 绕过、共享 CDN IP、已有防火墙顺序和连接存量必须有明确处理或明确限制。
- 只修改带精确 rosboard 所有权身份的 RouterOS 对象；不得覆盖或删除用户规则。
- 规划和应用必须读回 RouterOS 实际状态，发现顺序冲突或不可证明的终端身份时阻止应用。
- 本任务规划阶段只做调研与设计；进入实现前仍需用户审阅 `prd.md`、`design.md` 和 `implement.md`。

## Acceptance Criteria

- [x] 识别现有域名来源、RouterOS 物化、终端监控和写入边界中的复用点。
- [x] 对照 MikroTik 官方文档确认 DNS address-list、防火墙时间匹配、规则计数、连接跟踪、Kid Control 和 Scheduler 的适用边界。
- [x] 只读确认现网 RouterOS 版本、DNS、IPv4/IPv6、防火墙顺序、终端寻址和时区状态。
- [x] 确认所有 RouterOS 均按设备独立配置，不自动跨设备下发或联动。
- [x] 确认默认按设备自动跟随地址、固定 IP 仅作为无可靠设备身份或高级设置；单成员暂时不可解析不再全局 fail-closed。
- [x] 确认第一版不强制接管 DNS，接受外部 DNS、DoH、VPN、代理或直连 IP 绕过的边界。
- [x] 确认每日配额按 RouterOS 规则计数器推导的网络活跃时间累计，并确定默认采样、门槛和空闲窗口。
- [x] 确认 rosboard 离线时保持 RouterOS 当前状态，未观测区间不扣时、不补算。
- [x] 确认 TCP reset、其他协议 drop，且不做 HTTPS 本地说明页。
- [x] 通过 MikroTik 官方文档和现网 RouterOS `console/inspect` 确认 IPv4/IPv6 `reject-with=tcp-reset` 为官方支持语法。
- [x] 确认固定时段使用允许窗口语义，空窗口全天允许，配额只在允许窗口内累计。
- [x] 确认提供临时放行至本地午夜和重置当日用量，并保留审计。
- [x] 确认来源可同时用于策略路由和访问控制，并同意迁移当前物理 shared address-list 模型。
- [x] 确认逻辑规则支持多终端、多来源或整个互联网；多个终端共享同一每日配额池并按成员有效活跃时间累加。
- [ ] 完成经用户审阅的技术设计、分阶段实施计划和验证矩阵。
