# Rosboard 前端 UI 重塑实施计划

## Ordered Checklist

1. 建立视觉基础
   - 新增颜色、排版、间距、圆角、阴影、层级和动效令牌。
   - 新增 Rosboard 品牌 SVG 与 favicon。
   - 建立基础 reset、排版、按钮、输入、焦点和 reduced-motion 规则。
   - 删除未引用的 Vite 模板 `App.css` 及模板资产引用（若确认无消费者）。

2. 拆分无行为变化的前端基础模块
   - 移出 API/领域类型、格式化函数、排序函数和导航元数据。
   - 建立 `AppShell`、导航、页头、Panel、状态、工具栏、表格、标签页、弹窗和反馈组件。
   - 保持当前 fetch、刷新周期、默认筛选和备注保存语义不变。

3. 实现应用外壳和响应式导航
   - 桌面固定深色侧边栏、浅色内容区和统一顶栏。
   - 平板/手机抽屉导航、遮罩、关闭与焦点行为。
   - 全局错误、警告、更新时间和刷新控制统一展示。

4. 将已批准的概念方向落到系统概览
   - 重做指标卡、实时流量、设备/健康信息和接口摘要的层级。
   - 使用真实 API 字段，不创造后端不存在的风扇、电源或告警数据。
   - 在 1440、1024、768 和 375px 下完成首轮浏览器检查，作为后续页面的样板门槛。

5. 重塑线路、终端列表和终端详情
   - 统一工具栏、排序、筛选、分页、状态标记和操作链接。
   - 保留终端默认在线筛选、非活动设备切换和 34px 桌面工具栏约束。
   - 实现移动端关键字段与行详情；连接明细只在局部容器允许横向滚动。
   - 完成备注弹窗的焦点管理、关闭行为和提交反馈。

6. 重塑负载、协议、策略和路由页面
   - 统一历史图表、时间范围控制、表格、空状态和真实性说明。
   - 保留 RouterOS 原生数据与端口估算的明确区分。
   - 对空策略/空路由提供可理解的只读空状态。

7. 全面交互与响应式收口
   - 检查 hover、pressed、disabled、loading、error、empty 和 focus-visible 状态。
   - 检查 375、768、1024、1440px，无页面级非预期横向滚动。
   - 检查键盘导航、触控目标、对比度和 reduced-motion。

8. 构建与真实数据验证
   - 运行前端 lint、TypeScript/Vite production build。
   - 运行 Go 全量测试，确认嵌入输出和后端未回归。
   - 使用本地 API 或开发代理数据浏览所有一级页面、终端详情、弹窗、加载、错误和空状态。
   - 检查 `git diff --check` 和最终改动范围。

## Validation Commands

```bash
cd web && npm run lint
cd web && npm run build
go test ./...
git diff --check
```

浏览器检查视口：`375x812`、`768x1024`、`1024x768`、`1440x900`。

## Review Gates

- Gate A：视觉令牌、品牌和 AppShell 完成，系统概览与批准方向一致。
- Gate B：线路与终端列表/详情完成，现有筛选、刷新、排序、分页和备注行为无回归。
- Gate C：负载、协议、策略、路由完成，全部状态和响应式检查通过。
- Final：前端 lint/build、Go 测试、浏览器全页面检查和 diff 检查通过。

## Risky Files and Rollback Points

- `web/src/App.tsx`：包含所有现有业务交互；先机械拆分再改视觉，避免同时改变行为和结构。
- `web/src/index.css`：现有全部有效样式；引入新样式树后确认入口顺序，避免新旧选择器互相覆盖。
- `web/package.json`：若增加图标依赖，只增加一个小型成熟库并同步 lockfile。
- `internal/ui/dist`：生产构建会刷新嵌入资产；验证源构建后再纳入最终变更。
- 每个 Review Gate 保持可构建，可通过撤销该阶段的源文件与生成资产整体回滚。
