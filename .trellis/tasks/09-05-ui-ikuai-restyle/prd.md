# Requirements: compact iKuai-inspired Rosboard

## Status and outcome

Replanned on 2026-09-07 after the user rejected the intervening restyle. The compact study’s appearance and the subsequent explicit overview exceptions have been approved. This plan is ready for review; implementation must wait for a new instruction. Previous milestone completion and acceptance statements are historical, superseded by this status.

Make Rosboard a restrained, compact Chinese network administration interface consistent with the approved study: narrow navigation, clear hierarchy, gentle blue emphasis, pale grouped metrics, dense readable tables and orderly forms. iKuai 4.0 is the design reference; Rosboard's actual data and workflows remain the product contract.

## Required scope

- Apply the visual system across authentication, onboarding, empty-device state, shell, overview, all monitoring pages, target library, routing, access control, recognition, settings, dialogs and error/empty/loading states.
- Preserve every existing functional entry, button action, field, filter, sort, pagination option, state indication, validation, confirmation and asynchronous feedback.
- Preserve the four-step policy workflow, plan generation, warnings, acknowledgements and application safeguards.
- Preserve light/dark appearance and responsive navigation; do not optimize only the large desktop overview.
- Preserve the approved preview in version control with provenance and reproduction instructions, so another agent can work without the conversation or the original local service.
- Layout, order, control appearance, spacing and grouping may change. Removing behavior or information requires explaining the specific proposed deletion and receiving user agreement. No deletions are approved by this plan.

## Non-goals

No backend/API/schema/permission/policy semantics rewrite, framework replacement, new UI library, fictional monitoring metrics, new device capabilities, iKuai branding copy, deployment or merge in this planning round. Demo-only controls do not become new product requirements.

## Acceptance

The implemented interface must match the compact study in navigation proportions, color restraint, typography and page hierarchy, except the four overview header cards and quick-link module explicitly adopted from the pinned branch reference. The overview left rail must read interface information → quick links → device information. Every checklist item must have a real destination and verified behavior, including conditional and destructive-action states. Automated checks alone do not establish visual acceptance. The user must review the actual implementation; production acceptance and merge remain subject to repository gates.
